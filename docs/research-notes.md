## 1. 游戏设计 / 玩家心理

| 资料 | 关键结论 | 落到《诡辩之术》 |
| --- | --- | --- |
| 《游戏设计艺术》Jesse Schell（[百科](https://baike.baidu.com/item/%e5%85%a8%e6%99%af%e6%8e%a2%e7%a7%98%e6%b8%b8%e6%88%8f%e8%ae%be%e8%ae%a1%e8%89%ba%e6%9c%af)） | 用「透镜」反复提问：玩家想要什么、选择是否有意义、反馈是否清晰 | 每个选择都要能改变观众/评委/关系，而不是装饰 |
| 《通关升级》/《Rules of Play》 | 规则即表达；核心循环要短、可重复、有变化 | 找漏洞 → 命名 → 反驳，单回合 ≤ 2 分钟 |
| 自我决定论 SDT（[官方](https://selfdeterminationtheory.org/theory/)） | 自主 / 胜任 / 联结被满足才有高质量动机 | 选持方、选漏洞、选结辩=自主；拆解正确率=胜任；对手也有苦衷=联结 |
| 心流（Csikszentmihalyi） | 挑战-技能平衡、目标清晰、即时反馈 | 难度靠干扰项相似度递进；每步都有观众跑票反馈 |
| Octalysis（[框架](https://octalysisgroup.com/octalysis-framework/)） | 8 驱动力，白帽（意义/成就/自主）适合长期，黑帽（稀缺/损失）易伤信任 | 白帽为主；只在自由辩论用一次 10 秒紧张 |
| Hooked（Nir Eyal） | 触发→行动→可变奖励→投入 | 只用「投入」做留存（笔记/图鉴/关系）；不做 FOMO/体力 |
| 《Make It Stick》（[书评](https://pmc.ncbi.nlm.nih.gov/articles/PMC13418679/)） | 检索练习、间隔、交错、合意困难；「看起来会了」是幻觉 | 找漏洞=检索；赛后 3 题；每周混入旧谬误 |
| 峰终定律 + 叙事游戏研究（[ACM](https://dl.acm.org/doi/epdf/10.1145/3582437.3587195)） | 记忆由峰值与结尾决定 | 结辩做成峰值，尾声留人味 |
| 游戏可用性/体验研究方法综述（[Zenodo](https://zenodo.org/records/22180341)） | 测试分可用性与体验两层：能不能玩通、玩得开不开心 | 自动化测「能玩通」，人工模拟测「开不开心」 |

## 2. 表现层（像素 / UI / 可读性）

- Godot 性能与优化官方清单（[4.3 docs](https://docs.godotengine.org/es/4.3/tutorials/performance/general_optimization.html)）：少用逐帧重建、复用节点、避免每帧分配；我们已在换视图时才重建，可继续减少 tween/重复刷新。
- 像素风 UI：**低分辨率栅格 + 直角 + 2px 描边 + 有限色板**；字号宁可大不可小，长文本用行距和分屏解决（[网易：像素风 UI 设计](https://m.163.com/dy/article/K0RE15L30526K8VB.html)）。
- 像素字体回潮与生产可用性（[ic.work](https://www.ic.work/article/modern-pixel-fonts-production-readiness)）：优先系统 CJK 字体保证可读，像素字体只用于标题/数字，避免正文用像素字体（中文小字号会糊）。
- 现有实现结论：正文 14–20px、行距 1.4 左右；关键句加色不加粗体；按钮高度 ≥ 42px 方便点。

## 3. 文案（去 AI 味）

- 游戏人物对话写作经验（[GameRes](https://www.gameres.com/207125.html)）：每句要有「意图」和「潜台词」，不要解释设定；用具体名词代替抽象形容词。
- 去 AI 味参考（[anti-ai-guide](https://github.com/JIRBOY/ai-novelist/blob/main/references/anti-ai-guide.md)、[language-naturalization](https://github.com/Yuki001/Novelist-Skills/blob/main/.claude/skills/novelist-write/references/language-naturalization.md)）：
  - 少用排比、对仗、"不是…而是…"三连；
  - 多写半截话、口头禅、跑题、停顿；
  - 人物说话要符合身份（领导/实习生/亲戚）与场合；
  - 同一个意思不要连续两句用同一种句式；
  - 具体到数字/地点/物件（「十一点」「全勤」「四趟」「旧闻」）。
- 自查规则（每场剧本收尾必跑）：
  1. 随机抽 5 句，删掉「其实/确实/某种程度上」后是否更自然；
  2. 是否存在连续 3 句同长度；
  3. 是否有人物只负责讲道理、没有私心；
  4. 高潮句能否被截图转发（短、狠、可复述）。

## 5. 游戏文案与剧情推进（本轮新增，来源：网易文案策划必修课 / 对白设计方法）

- 来源：[网易文案策划必修课](https://www.gameres.com/907054.html)、
  [对白与互动选择设计方法](https://github.com/zenstory-ai/novel-to-game/blob/8cdad805cfa64568a56275e6b46bba6df86dd745/skills/game-world-design/references/dialogue-design-method.md)
- 可落地的规则（已用于四场剧本）：
  1. **一句话一个动作**：试探 / 交换 / 划界 / 推责 / 威胁 / 保护 / 转移 / 求证 / 拒绝。
     先定动作，再写句子；每句至少完成一项（推进局面、增加期待、显露人物、改变权力）。
  2. **双方议程不能一致**：表面谈同一件事、实际争不同结果。议程一致就是复述，应删。
  3. **对话长度≈权力位置**：掌控者短而冷，被动者多而急；权力反转时长度也要反转。
  4. **不要每句都成功**：让反对方看穿、反证、改公开范围、把对方的词反过来用。
  5. **禁科普嘴**：设定和原理不能整段讲，拆成压力下挤出的半句话 + 身体反应 + 留白。
  6. **信息的进入方式**：先给可观察载体（证词、截图、跑四趟、旧闻），再给直接支持，
     最后才给推断；新揭示可以改变旧证据的意义，不能改写已发生事实。
  7. **场景五问**：删掉本场损失什么、焦点人物想让谁做什么、谁反制、本场让什么变得不可逆、
     哪项未付代价推动下一场。四场剧本都按这个检查过。
  8. **避免模板化**：过度解释、过度收口、每轮同样长度/句式、信息密度均匀、代价即时结清。
  9. **保护不整齐的部分**：方言、口吃、急话、只有这个人物会用的比喻，润色时别抹平。
- 本轮据此做的文案修订：三处「对仗式笔记」改成具体事实复述；三处场景开场补了
  「枸杞 / 凉鱼 / 磨豆机 / 屏幕光」这类可观察细节。
